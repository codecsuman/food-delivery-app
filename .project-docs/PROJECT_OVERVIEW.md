## 📌 High-Level Summary

**Suman Food** is a production-ready, full-stack food ordering and restaurant management platform built on the **MERN stack**. It supports:

- **Customers**: Browse restaurants, search/filter, cart + checkout (Stripe + COD), live order tracking on a map, reviews, reorder, cancel with auto-refund.
- **Restaurant Owners**: Manage **multiple** restaurants with drag-pin geolocation, menu CRUD with Cloudinary images, order management, featured items, driver assignment.
- **Real-time**: Socket.IO live driver tracking with ETA, route polyline, per-order authentication, immediately replayed last-known driver position, and a 10 s polling fallback.

## 📡 API Endpoints (v1)

All routes prefixed with `/api/v1`. Auth via HTTP-only `token` cookie.

| Domain | Key Endpoints |
|--------|---------------|
| **Auth** | `POST /user/signup`, `POST /user/login`, `POST /user/logout`, `GET /user/check-auth`, `PUT /user/profile/update` |
| **Restaurant** | `POST /restaurant/` (multipart, lat/lng required), `GET /restaurant/` (`?restaurantId=`), `PUT /restaurant/` · `PUT /restaurant/:id`, `GET /restaurant/my-restaurants`, `GET /restaurant/all`, `GET /restaurant/search`, `GET /restaurant/filters`, `GET /restaurant/:id`, `DELETE /restaurant/:id`, `GET /restaurant/order`, `PUT /restaurant/order/:orderId/status` |
| **Menu** | `POST /menu/` (multipart, `restaurantId` optional), `GET /menu/`, `GET /menu/popular`, `PUT /menu/:id`, `DELETE /menu/:id`, `GET /menu/restaurant/:restaurantId` |
| **Order** | `POST /order/checkout/create-checkout-session` (stripe\|cod), `POST /order/webhook` (raw body + signature), `GET /order/`, `GET /order/session/:sessionId`, `GET /order/:orderId`, `POST /order/:orderId/cancel` |
| **Map** | `GET /map/pincode/:pincode`, `GET /map/autocomplete?q=`, `POST /map/validate-address`, `POST /map/check-delivery`, `POST /map/restaurant/distance`, `POST /map/tracking/route`, `POST /map/delivery-time`, `POST /map/reverse-geocode` |

> **Route-order gotcha:** `/order/session/:sessionId` must stay **before** `/order/:orderId`, and the Stripe webhook must be registered **before** `express.json()` (it needs the raw body).

## ⚙️ Environment Variables

### Backend (`server/.env`) — **Never commit**
```env
PORT=8001
NODE_ENV=development
FRONTEND_URL=http://localhost:5173
MONGO_URI=mongodb://127.0.0.1:27018/suman_food?replicaSet=rs0
SECRET_KEY=your-super-secret-jwt-key-min-32-chars
STRIPE_SECRET_KEY=sk_test_...
WEBHOOK_ENDPOINT_SECRET=whsec_...
CLOUDINARY_CLOUD_NAME=...
CLOUDINARY_API_KEY=...
CLOUDINARY_API_SECRET=...
OPENCAGE_API_KEY=...
DELIVERY_SPEED_KM_PER_MIN=0.333
MAX_DELIVERY_RADIUS_KM=10
MIN_ORDER_AMOUNT=50
```

`server/index.ts` validates all required variables (and `SECRET_KEY` length ≥ 32) at startup and exits with a clear error if any are missing.

> **Transactions:** COD checkout and webhook confirmation use MongoDB transactions when the deployment is a replica set or `mongos`. Atlas provides this automatically; Windows development uses `npm run mongo:start` (single-node `rs0` on port 27018). On a standalone server the API uses compensating writes (delete/revert + decrement menu counters) so local checkout still works, and `/health` reports `transactions.supported: false`.

### Frontend (`client/.env`)
```env
VITE_API_BASE_URL=http://localhost:8001/api/v1
VITE_SOCKET_URL=http://localhost:8001
```

### Test overrides (optional)
```env
MONGODB_TEST_URI=mongodb://...       # use an existing DB instead of in-memory
MONGOMS_SYSTEM_BINARY=C:\path\mongod.exe   # reuse installed binary (no download)
```

> ⚠️ In production, use **full HTTPS backend URLs**. Set `NODE_ENV=production` as a real env var on the hosting dashboard.

## 📦 Order Lifecycle

```
Placed → Confirmed → Preparing → On the Way → Delivered
   │
   ├── Cancelled (customer, before Delivered)
   └── Payment Failed (Stripe only, via webhook)
```

- Stripe orders: `pending` → `confirmed` on `checkout.session.completed` webhook
- COD orders: created directly as `confirmed`
- Cancel: allowed only while status transition is legal; auto refund for Stripe
- `outfordelivery` enables live Socket.IO tracking
- Stripe retries are ignored once an event ID has been processed (idempotent)

### Cart & Checkout Rules
- A cart may contain items from **one restaurant only**. The restaurant is derived from `menu.restaurant` on the cart items, not from a global store.
- Mixed carts show a warning and cannot be checked out.
- Delivery fee comes from the cart's restaurant.
- Client-supplied prices are ignored; totals are recalculated from the database.

## 🐛 Known Issues / Gotchas

| Issue | Workaround / Fix |
|-------|------------------|
| Login → 401 on next request (cross-origin) | Ensure `NODE_ENV=production` is set **as env var** on host, backend served via HTTPS, `FRONTEND_URL` exact match |
| "Restaurant location required" | Owner must drag pin / tap "Use My Location" in Dashboard → Restaurant |
| Stripe "amount too small" | Cart total < `MIN_ORDER_AMOUNT` (default ₹50) — caught server-side |
| `Transaction numbers are only allowed on a replica set` | Run `cd server && npm run mongo:start` and use `mongodb://127.0.0.1:27018/suman_food?replicaSet=rs0`, or use MongoDB Atlas. Standalone still works via compensating writes; check `GET /health` → `transactions` |
| Port in use | `cd server && npm run kill`, then `npm run dev`; the dev preflight check refuses to start a second backend |
| MongoDB connection failed | Check `MONGO_URI`, ensure Mongo is running. Local: `npm run mongo:start` → port `27018` |
| Stripe webhook not firing locally | `stripe listen --forward-to localhost:8001/api/v1/order/webhook` |
| Live tracking wrong location | Verify restaurant/customer `location.coordinates`; the pin/GPS position is authoritative, and the server replays the persisted driver position on join |
| Live map never updates | Socket.IO may be blocked; the page polls every 10 s. In prod set `VITE_SOCKET_URL` or a full `VITE_API_BASE_URL` (socket origin is derived from it) |
| Test suite first run slow | Install MongoDB locally (auto-detected) or set `MONGOMS_SYSTEM_BINARY`; otherwise mongodb-memory-server downloads a binary |

## 🔐 Security Notes

- Passwords hashed (bcrypt), never returned
- JWT in HTTP-only cookies (secure + sameSite: none in prod)
- Startup validation for required secrets (`WEBHOOK_ENDPOINT_SECRET`, `SECRET_KEY` ≥ 32 chars, etc.)
- Stripe webhook signature verification + replay protection
- Server-side price verification — client prices are never trusted
- Server-side ownership checks on orders, menus, restaurants, reviews and tracking
- Zod validation for body/query/params; `sanitizeBody` blocks Mongo operators
- Rate limiting with IPv6-aware keys + `trust proxy`
- Helmet CSP/HSTS; CORS allow-list
- `.env` files git-ignored; rotate any leaked credentials
